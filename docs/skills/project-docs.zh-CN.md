# 整理项目文档（中文对照）

> 对应[英文执行版](../../skills/project-docs/SKILL.md)。本稿供对照阅读，执行以英文为准；修改英文时同步更新本稿。

技能名：`project-docs`

适用场景：整理项目文档，合并重复内容，维护 `docs/README.md`，修复引用，归档不再使用的工作记录。用于文档结构与生命周期维护；大幅改写正文时使用写作技能。

阅读[共用约定](conventions.zh-CN.md)。

1. 检查相关文档及其引用。合并或删除前，明确用途、读者、状态、权威来源和独有内容。
2. 保留合理的主题组织方式和已有命名。按需创建目录，依据共用原则判断保留、合并或结束使用。
3. 将 `docs/README.md` 维护为精选的现行入口，说明用途、读者和必要的状态。适当时从根 README 链接；只有导航确实困难时才增加局部索引。
4. 现行内容在原处维护，将有历史价值的过时部分拆分归档；有保留价值且不再指导当前工作的记录整体归档。使用所属主题的归档和既有命名，保留理解归档内容所需的上下文，记录归档日期、原因和替代文档（如有）；结束旧计划前应用共用的方向变更规则。
5. 移动或替换后修复指向它们的链接和当前工作入口，保留追溯历史决策所需的引用。

大幅改写人类文档使用 `project-docs-human`，编写 AI 工作文档使用 `project-docs-agent`。单独写作不需要整理整个仓库。

核查改动过的内容和引用，汇报改动及重要未知事项。修改限于用户请求的文档范围。
