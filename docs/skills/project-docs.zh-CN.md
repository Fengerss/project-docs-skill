# 整理与重构项目文档（中文对照）

> 对应[英文执行版](../../skills/project-docs/SKILL.md)。本稿供对照阅读，执行以英文为准；修改英文时同步更新本稿。

技能名：`project-docs`

适用场景：整理、修订和重构项目文档，收敛重叠的文件与目录，维护 `docs/README.md`，修复引用，归档不再使用的记录。用于结构、生命周期和过时内容清理；大幅改写正文时按需配合写作技能。

阅读[共用约定](conventions.zh-CN.md)。

1. 在请求范围内检查相关文档、目录及其引用，包括代码、测试、脚本、配置和封存工件中的使用方。合并、移动或删除前，明确用途、读者、状态、权威来源和独有内容。
2. 根据内容与引用比较用途相近的目录，说明差异并推荐保留位置，合并前询问用户保留哪个；用户已有明确选择时直接沿用。复用合理的主题组织方式，按需创建目录。
3. 将重叠文件收敛为一个持续维护的版本，承接独有的有效内容。依据已核实的来源修订过时说明和混乱结构。
4. 将有保留价值且不再使用的文档移入所属主题的归档；固定路径使用方或封存引用要求保留原位时，在导航中标明这些材料的历史用途。现行与历史内容混杂时，保留有效定义，拆出有价值的过时部分归档，直接将正文中过时的执行指向改为当前指导及历史链接。文档大部分已过时但仍需提供现行版本时，先归档原稿，再在原维护路径重写。保留理解归档内容所需的上下文，沿用既有归档命名，记录日期、原因和替代文档（如有）；结束旧计划前应用共用的方向变更规则。
5. 合并或归档后，在所属的现行文档中更新历史链接。`docs/README.md` 只维护简洁的文档入口，适当时从根 README 链接。
6. 修复引用链接、受影响的文件使用方和当前工作入口，再移除已清空的重复目录。仅对无法更新的引用保留旧路径跳转，保留追溯历史决策所需的引用。

大幅修订时，按受众配合 `project-docs-human` 或 `project-docs-agent` 完成改写。单独写作不需要整理整个仓库。

核查改动过的内容和链接、受影响的文件使用方，确认独有的有效内容未丢失、重复的现行版本已收敛。确认现行文档没有重复或被取代的执行段落，有保留价值的停用记录已归档或明确原位保留。从当前入口按读者的实际任务走查，确认能找到权威且持续维护的信息，历史指令与当前工作明确区分。汇报改动及重要未知事项。

## 示例

`docs/research/findings.md` 混有仍适用的结论和历次试验。结论原位保留，历史细节迁入所属主题的归档，并在 `findings.md` 末尾登记简短历史索引。沿用已有路径和归档命名，以下结构仅作示意。

```text
docs/
├── README.md                  # 文档入口
├── todo/
│   ├── progress.md            # 当前任务及其历史索引
│   └── archive/
│       └── past-work.md       # 历史任务记录
└── research/
    ├── findings.md            # 仍适用的结论及其历史索引
    └── archive/
        └── past-experiments.md # 历次试验与被替代方案
```
