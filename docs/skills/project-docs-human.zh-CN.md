# 写给人看的项目文档（中文对照）

> 对应[英文执行版](../../skills/project-docs-human/SKILL.md)。本稿供对照阅读，执行以英文为准；修改英文时同步更新本稿。

技能名：`project-docs-human`

适用场景：编写、更新和审阅面向人的项目说明、指南、设计、规格与状态。当人需要理解项目、完成操作或评估决策时使用；AI 也使用同一份文档。

阅读[共用约定](conventions.zh-CN.md)。

- 明确读者需要理解或完成什么。只有缺失信息会实质影响结果时才询问。
- 先讲结论、关键变化或需要采取的行动，让读者扫读时就能抓住重点。
- 每段围绕一个中心。并列的发现、条件、问题或建议适当分点，有先后顺序的操作使用编号；每点先简要概括，再补充必要的解释或证据。因果解释保留为简短段落。
- 使用清楚的语言，解释必要术语，将技术细节与其影响联系起来；删去重复说明和无关背景，保留必要的上下文、条件、证据与限制。
- 修订时直接精简、重组正文；只有导航仍有需要时，才补充概览或导读。
- 设计文档解释职责、关系和原因；指南提供可用步骤和预期结果。按读者需要选择结构，不强套模板。
- 当前状态概述已核实的里程碑、结果和重要阻塞，任务执行细节保留在工作记录中。

对照来源核查改动过的内容、示例和链接。导航发生变化时更新相关入口，汇报仍未核实的重要事实。
